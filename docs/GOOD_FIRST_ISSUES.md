# Good first issue candidates

These are concrete issue drafts for maintainers to open after confirming scope. They have not been posted automatically.

1. **Add Skill: Lighthouse performance review** — define a focused manifest, capability declarations, instructions, validation, and contributor docs example.
2. **Add Skill: TypeScript API documentation review** — check exported contracts, examples, errors, and versioning without granting tools.
3. **Improve Skill documentation examples** — add one valid and two invalid manifests with expected validator output.
4. **Add a minimal Team Pack example** — create a small, professional non-development pack after product review; avoid filler roles.
5. **Translate contributor docs** — propose one maintained language and document how translated pages track the English source.

Good first issues should have a bounded outcome, named files, acceptance criteria, and a maintainer available to review them.
