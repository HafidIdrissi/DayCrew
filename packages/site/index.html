01

From an idea to a team at work.

You work with one Manager. DayCrew keeps Tasks, ownership, handoffs, and the decisions reserved for you visible at every step.

  1. Open a WorkspacePoint DayCrew at a project folder on your machine.
  2. Create a TeamInstall a Team Pack or build your own Manager and Members.
  3. Give a GoalThe Manager plans Tasks and delegates them to specialists.
  4. Team worksMembers coordinate through real Tasks and recorded handoffs.
  5. You decideNeeds You collects approvals, decisions, blockers, failures, and reviews.
02

Five things to know

DayCrew has a small vocabulary. Everything in the app is built from these.

Workspace

A folder you choose. All DayCrew state lives in its .daycrew/ directory and never leaves your machine.

Team

One Manager plus any set of specialist Members, each with a role, instructions, and an AI Engine.

Task

A unit of work with an owner, dependencies, handoffs, a status, and a recorded result.

Skill

Reusable instructions and workflow knowledge. A Skill teaches; it never grants tool or filesystem access.

Needs You

The one queue for approvals, decisions, blockers, failed Tasks, and review requests.

05

Local first, and specific about it

DayCrew is a local application. The public site you are reading is static and separate from it.

Your Workspace stays yours

Teams, Tasks, approvals, and activity are written under the project folder’s .daycrew/ directory as local JSON and JSONL.

Loopback only

The local API listens on 127.0.0.1 and rejects non-local browser requests and cross-site origins.

No account, no cloud

There is no sign-up, no telemetry service, and no multi-user sync. Engine credentials stay managed by each engine’s own CLI.

Confined actions

Provider actions are bound to the selected Workspace root, and the autonomy policy decides what pauses for you.

06

Bring the engine. Keep the model.

Provider capabilities differ. DayCrew labels those differences instead of smoothing them over. These are the engines DayCrew actually integrates today.

Claude CodeProduction ready

The actionable alpha engine: Workspace-confined writes, DayCrew approval bridging, session resume, and Skills.

Approved shell commands still run with your local user’s permissions.
CodexRead-only preview

Planning and review only. Writes and native approval bridging are disabled.

Never selected by Auto.
Gemini / AntigravityRestricted experimental

Workspace confinement and provider tool controls are not enforceable enough for normal work.

Never selected by Auto. Requires explicit consent in the app.
Deterministic demoDemo and tests

A simulated engine that exercises the full DayCrew lifecycle without any credential.

Clearly labelled everywhere. Its output is never real AI execution.

Read the Claude, Codex, and Gemini security notes before enabling a real engine.

07

Install and run it locally

DayCrew v0.1.0-alpha is installed from source. You need Git, Node.js 20.19+, and Corepack with pnpm 10.

1 · Get DayCrew

git clone https://github.com/daycrew/daycrew.git
cd daycrew
corepack enable
pnpm install --frozen-lockfile
pnpm build

2 · Start the app and its local server

pnpm dev

The app opens at http://127.0.0.1:5173 and its local API listens on http://127.0.0.1:5005.

3 · Open a Workspace

On first run, create or open a folder as a Workspace, then install the Software Development Team Pack and give your Manager a goal.

Keep the terminal running while you use DayCrew. Open the local address after the server says it is ready.

Platform notes and troubleshooting are in Installation. Current constraints are listed in Known limitations.

08

Try it without an AI Engine

Demo Mode is a deterministic, clearly labelled simulation. It runs in its own isolated Workspace and never mixes with real data.

node packages/cli/dist/bin.js demo create --path <empty-folder>

# macOS / Linux
DAYCREW_WORKSPACE_ROOT=<empty-folder> pnpm dev

# Windows PowerShell
$env:DAYCREW_WORKSPACE_ROOT='<empty-folder>'; pnpm dev

The demo run exercises planning, delegation, handoffs, a real Needs You approval, same-session resume, review, and completion through persisted DayCrew state.

The provider action is simulated. Use Claude Code in a disposable Workspace when you want real file changes.
